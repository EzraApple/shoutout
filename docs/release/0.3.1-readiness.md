# ShoutOut 0.3.1 release preparation

Candidate version: **0.3.1, build 22**, arm64, macOS 15 or later. This keeps the
architecture policy of the current public release.

## Included changes

- Retain and pause the recording engine between takes. Hardware capture stops;
  no pre-roll is collected. Rebuild after sleep or an audio configuration change.
- Merge `ezra/indicator-anchors` through `26c7d09`: draggable placement, saved per
  indicator style/display, native crab dragging, hover recovery, and style changes.
  Glass and Classic support four edges; Crab supports left and right.
- Merge `ezra/media-dimming` through `7c6769a`: Do nothing / Dim audio, with a
  10% ceiling. The preference survives migration.
- Serialize dimming and restoration across short and successive recordings. Keep
  the saved volume until restoration succeeds, including after command failure.
- Make the indicator hover regression use an injected pointer instead of the
  CI machine's real pointer and window-placement constraints.

## Performance evidence

The controlled built-in microphone experiment compared identical capture work,
rotated variant order, and excluded each variant's first take. Eleven measured
takes per variant gave these medians:

| Recorder setup | Engine ready | First raw buffer |
| --- | ---: | ---: |
| New engine per take | 160 ms | 264 ms |
| Retained paused engine | 50 ms | 156 ms |

Paired savings were approximately 109 ms to ready and 108 ms to the first buffer.
These measure startup, not transcription or time to pasted text. Normal use of
the installed trial then measured eight repeat starts at 53–62 ms, median 57 ms;
release-to-paste was 171–250 ms, median 180 ms. A later start after roughly three
minutes idle still reused the graph and took 68 ms.

An isolated virtual-input probe found about 0.64 MiB of extra live heap for the
retained graph across eight cycles. This is not a whole-app physical-memory
estimate for every microphone. Raw audio, personal transcripts, runtime logs,
and screenshots remain outside Git.

## Verification and limits

- Production recorder harness: 13 capture/replay/simulated-sleep cases; 12 active
  input changes; four rapid double-switch cases. Every run restored the original
  input and ended with hardware inactive.
- Local menu-bar screenshots showed the orange microphone dot during capture and
  absent after pausing. Normal Fn recordings successfully transcribed and pasted.
- Dimming regression tests use injected volume I/O, including in-flight writes,
  pending reads, successive takes, and failed restoration. They never change the
  user's system volume.
- Build, model smoke, repository checks, and the website build run before release.
  The frozen Mini model, tokenizer, and speech worker are unchanged.
- Physical sleep/wake, Bluetooth/USB removal, and physical dragging across multiple
  displays/full-screen Spaces remain unverified. The user selected simulated sleep
  and asked to stop further timing tests. Never use an iPhone/Continuity input for
  automated checks.

## Publication boundary

This branch stages the next version's download defaults, release notes, history,
and signed feed. They take effect only when the release is published. Do not merge
or deploy those pointers until the final DMG and notes exist at their target URLs.

Follow the [app-update workflow](../../.agents/skills/shoutout-app-update/SKILL.md).
Prepare the signed app/DMG with `SHOUTOUT_DMG_HEADLESS=true UNIVERSAL=false make
release-dmg`, supplying the frozen Mini asset directory, existing Developer ID,
Sparkle public key, and notarization profile. The local trial stays installed while
the separate distribution bundle is built. Check the final bundle has the public
updater key/feed and has neither trial flag enabled.

After publication is authorized:

1. Upload the exact notarized DMG and authored notes using `make blob-upload-dmg`.
2. Confirm the uploaded bytes match the candidate's checksum and signed feed.
3. Set the production download version and URL, then merge/deploy the release.
4. Run `make release-verify-live` and verify an older app's Sparkle update path.

Local preparation does not upload to Blob, change production environment values,
merge to main, or deploy the website.
